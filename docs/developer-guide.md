# Developer Guide

A technical guide for anyone maintaining or developing the GLINT website.

## Tech Stack

| Tool | Purpose | Docs |
|------|---------|------|
| [Astro 5](https://docs.astro.build/) | Static site generator — builds HTML pages from components | [astro.build/docs](https://docs.astro.build/) |

| [Formspree](https://formspree.io/) | Contact form submissions — sends emails | [help.formspree.io](https://help.formspree.io/) |

## Local Development

### Prerequisites

- **Node.js 18+** — [Download](https://nodejs.org/)
- **npm** (comes with Node.js)
- **Git** — [Download](https://git-scm.com/)

### Setup

```bash
# Clone the repo
git clone https://github.com/YOUR_ORG/glint-website.git
cd glint-website

# Install dependencies
npm install

# Copy environment variables (optional — only needed for TinaCMS cloud features)
cp .env.example .env
```

### Running Locally

**With TinaCMS editing (recommended for content work):**
```bash
npm run dev:tina
```
This starts both the TinaCMS local server (port 4001) and the Astro dev server (port 4321). You can edit content at http://localhost:4321/admin/index.html and see live changes.

**Without TinaCMS (faster, for code/styling changes only):**
```bash
npm run dev
```
Starts just the Astro dev server. Content is loaded from local files but you won't have the TinaCMS editing UI.

### Build Commands

| Command | What it does |
|---------|-------------|
| `npm run dev` | Start Astro dev server only (http://localhost:4321) |
| `npm run dev:tina` | Start TinaCMS + Astro together (CMS at /admin, site at /) |
| `npm run build` | Production build with TinaCMS (generates types, then builds static HTML) |
| `npm run build:local` | Production build without TinaCMS (uses existing content files) |
| `npm run preview` | Preview the production build locally |

## Configuration

### Environment Variables

Create a `.env` file in the project root (copy from `.env.example`):

```env
# Site URL — your production domain
SITE_URL=https://glintresearch.co.uk

# TinaCMS Cloud credentials
# Get these from https://app.tina.io → your project → Tokens
PUBLIC_TINA_CLIENT_ID=your_client_id_here
TINA_TOKEN=your_token_here
```

| Variable | Where to get it | Used for |
|----------|----------------|----------|
| `SITE_URL` | Your production URL | Sitemap generation, SEO meta tags |
| `PUBLIC_TINA_CLIENT_ID` | [app.tina.io](https://app.tina.io) → Project → Overview | TinaCMS cloud authentication |
| `TINA_TOKEN` | [app.tina.io](https://app.tina.io) → Project → Tokens → Content Token | TinaCMS API access |

Note: For local development with `npm run dev:tina`, these variables are optional — TinaCMS runs a local server that doesn't need cloud credentials.

### Setting Up TinaCMS Cloud

TinaCMS cloud is needed for the **/admin** UI to work in production (on Vercel). In local dev mode, it works without cloud.

1. Go to [app.tina.io](https://app.tina.io) and sign in with GitHub
2. Create a new project and connect it to your GitHub repository
3. TinaCMS will read the schema from `tina/config.ts` automatically
4. Go to **Tokens** and create a Content Token (read-only is sufficient for the site build; read-write if you want cloud editing)
5. Copy the **Client ID** (from Overview) and **Token** into your `.env` file and into Vercel's environment variables

Docs: [TinaCMS Setup Guide](https://tina.io/docs/frameworks/astro/)

### Setting Up Vercel

1. Go to [vercel.com](https://vercel.com) and sign in with GitHub
2. Click **"Add New Project"** and import the glint-website repository
3. Vercel auto-detects it's an Astro project — the defaults should work
4. Add environment variables in **Settings → Environment Variables**:
   - `SITE_URL` = your production URL (e.g. `https://glintresearch.co.uk`)
   - `PUBLIC_TINA_CLIENT_ID` = from TinaCMS
   - `TINA_TOKEN` = from TinaCMS
5. Deploy — Vercel will run `npm run build` automatically

**Custom domain setup:**
1. In Vercel, go to **Settings → Domains**
2. Add your domain (e.g. `glintresearch.co.uk`)
3. Vercel will show you DNS records to add at your domain registrar
4. Go to your registrar (e.g. GoDaddy, Namecheap) and add the DNS records
5. Wait for DNS propagation (usually a few minutes, can take up to 48 hours)

Docs: [Vercel Custom Domains](https://vercel.com/docs/projects/domains)

### Setting Up Formspree

The contact form on `/contact` submits to Formspree. The endpoint is hardcoded in the form's `action` attribute in `tina/pages/ContactPage.tsx`.

1. Go to [formspree.io](https://formspree.io) and create an account
2. Create a new form — Formspree gives you an endpoint URL like `https://formspree.io/f/xrezokpn`
3. Configure which email address receives submissions (in Formspree dashboard → Form Settings → Email)
4. The endpoint is currently set to `https://formspree.io/f/xrezokpn` in the code — update it in `tina/pages/ContactPage.tsx` if you create a new form

Docs: [Formspree Getting Started](https://help.formspree.io/hc/en-us/articles/360053371534)

## How Content Editing Works

### Via TinaCMS Admin UI (non-technical)

1. Go to `https://your-site.com/admin/index.html`
2. Log in with your TinaCMS credentials
3. Select a collection from the sidebar (e.g. "Team Members")
4. Edit fields, add/remove items
5. Click Save — TinaCMS commits the change to GitHub automatically
6. Vercel detects the change and rebuilds the site (takes ~1 minute)

### Via GitHub Directly (technical)

Content files are in `content/` and `src/content/page/`. They're MDX files with YAML frontmatter:

```yaml
---
title: "Rawen Kader"
role: "Chair"
bio: "My research focuses on..."
image: "/team/rawen-kader.jpg"
order: 1
---
```

Edit these files directly in GitHub or locally, commit and push. Vercel rebuilds automatically.

## Adding/Changing CMS Fields

To add a new field to a collection (e.g. adding a "LinkedIn" field to team members):

1. Edit the collection definition in `tina/collections/team.ts` — add the new field
2. Update the React component in `tina/pages/AboutPage.tsx` to render the new field
3. Run `npm run dev:tina` locally to test
4. Add content for the new field in the content files or via the admin UI
5. Commit and push — Vercel rebuilds, TinaCMS cloud syncs the schema change

---

## Adding a New Page

1. Create the Astro page: `src/pages/new-page.astro`
2. Create a page collection in `tina/collections/page.ts` (copy an existing one, change the name/fields)
3. Register it in `tina/config.ts`
4. Create the React component: `tina/pages/NewPage.tsx`
5. Create the content file: `src/content/page/new-page/new-page.mdx`
6. Add the route to the navigation in `src/components/Header.astro` and `src/components/Footer.astro`
7. Run `npm run dev:tina` to test
8. Commit and push

## Troubleshooting

**TinaCMS build fails with "Cannot query field" errors:**
The generated GraphQL schema is out of sync. Delete `tina/__generated__/` and rebuild:
```bash
rm -rf tina/__generated__
npx tinacms build --skip-cloud-checks
```

**TinaCMS admin shows "You are in local mode":**
This is normal during local development. In production, it connects to TinaCMS cloud using the environment variables.

**Content changes not appearing on the live site:**
Check Vercel's deployment dashboard — a new deployment should trigger within a minute of a GitHub push. If it's stuck, trigger a manual redeploy from the Vercel dashboard.

**Events still showing as "upcoming" after their date has passed:**
The site is statically built — events transition from upcoming to past at build time. Trigger a redeploy on Vercel, or set up a daily scheduled deploy via Vercel's cron feature.
